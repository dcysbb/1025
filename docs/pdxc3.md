# PDXC3 / PD1V/M 位移台

控制台左侧「位移台」页独立于真空联锁，保留运动与停止操作；连接模式、USB/TCP 方式、控制器序列号、IPv4 地址、端口、XYZ 通道映射、方向反转及单次步数上限集中在「硬件连接」页，并保存到运行数据目录的 `stage.json`。不会修改真空规、DAM 或阀门配置。旧配置默认继续使用 TCP。

CH1、CH2、CH3 必须各映射到一个轴；默认依次为 XYZ。修改映射前先断开位移台。网络地址留空时，通过官方 XA 的 `TLMC_DiscoverEthernetDeviceInfo` 搜索本机活动网段，每个网段最多 1024 个地址，仅查询指定端口（默认 TCP 40303），并按序列号和型号匹配。也可填写明确的 IPv4 地址。程序不自动改网卡设置，不扫描串口。

Windows XA 的原生 USB 枚举可能返回空字符串 `DeviceInfo.transport`。这是有效的 USB 标识，程序按 PDXC3 型号和完整序列号匹配后，将枚举原值（空字符串，非 NULL）传给 `Open`，诊断显示 `USB / 序列号`。USB 发现的额外连接列表为空，不加入 COM 或网口；USB 缺失不会回退到 TCP。TCP 发现结果若缺少传输标识则拒绝连接，不能借用 USB 空标识。

连接返回后再次核对 SDK `Device.transport` 与请求值。实机日志发现，当前 SDK 在指定网口无响应且 USB 可用时，可能返回实际使用 USB 的设备对象；此时传输标识为空，通信日志为 `USB FTDI`。控制台会拒绝这种与所选方式不一致的会话，不将其报为网口成功，也不通过它发送控制命令。

移动前先检查步频与加速度的有效读回范围（800–20000 步/秒、1–20000 步/秒²），再设置单步模式和步数。读回 0 等无效参数时，移动不会改变控制器设置或启用输出，须先在驱动参数区设置有效值。

连接只读取识别信息和状态，不启用驱动、不回零、不清零、不移动或自动优化。PDXC2AD 是官方转接线识别名称，允许用于 PD1/PD1V 开环台。保留 SDK 自动初始化主机产品信息，禁止自动校准、禁止自动载入整机全部通道参数；不调用实机不支持的手动型号设置。未连接的 CH2/CH3 不阻塞 CH1，运动状态未知或有实际运动时仍阻止新请求。

PD1V/M 无位置编码器，不提供绝对位置或毫米位置显示。本机 PDXC3 对 Relative 实测返回“不支持”。驱动改用有限 Jog：写入厂家 `TLMC_JogMode_SingleStep` 命名枚举（值 **2**；值 1 是连续模式）及步数，逐项读回一致后才允许启用输出并发送 JogForward/JogReverse，Move 的 param 为未使用的 0。单次还受控制器 20000 步上限约束。步频和加速度用于估计运动超时时间，超过预期即请求停止并锁存异常。脉冲对应的实际位移随驱动参数、负载、方向变化，步数上限不是机械限位。

「全部停止」向三个通道分别发送立即停止；一个通道失败也会继续尝试其余通道。通信中断不重发移动指令，也不会自动重新启用驱动。断开或后台退出时，如果曾发送移动或运动状态不确定，会先尝试停止；停止未确认时保留错误供操作员处理。恢复连接后需要重新手动操作，不回放之前的移动。

## 精细手动调节

XYZ 各自设置单次步数，并提供 1、10、100、1000 步快捷档位；超过单次上限的档位不可选。首次使用默认 10 步，上限不足时使用上限。步长仅存于当前浏览器，并按控制器序列号、运行模式、轴映射和方向隔离。恢复的旧步长超出新上限时会报错，不自动改小后下发。每张卡片显示映射通道、识别型号、使能状态及无法点动的具体原因。控制器工具展示开环命令计数，明确标注“非实测位置”。

键盘点动默认关闭。显式启用并聚焦控制区域后，左右键为 X 轴、上下键为 Y 轴，PageDown / PageUp 为 Z 轴，Esc 为全部停止。每次按键只下发一次有限步数，忽略自动重复和组合键；编辑输入框、打开弹窗、移出控制区域、窗口失焦、页面隐藏或设备状态失效时撤销键盘控制。停止有独立请求入口，不被移动请求的等待状态占用。

移动请求被接受后，`motion_pending` 保持为真，直到后续状态采样确认三个通道都空闲。该期间及请求发送期间的新移动直接拒绝，不排队补发；停止或断开会取消尚未下发的移动。状态未知时禁止移动，停止入口仍允许尝试。HTTP 应答丢失也不会自动重试，界面保留未确认提示，需要先停止并检查连接。

页面每 2 秒读取最近 20 条 `stage_move` 事件，操作后立即更新。结果分为 `submitted`（请求已下发）、`rejected`（未下发）、`unconfirmed`（结果未确认），同时记录逻辑方向、实际硬件方向、通道、步数和模式。旧事件缺少结果字段时显示“请求已下发”。记录不代表机械到位；记录读取失败会单独提示，不改变运动结果或屏蔽停止。

真实设备须先核对通道的 PD1V/M 及适配线配置。型号不匹配、过流、过温、运动异常和控制器 Error 阻止操作。本机 PDXC3 在 XA 已使能并能操作时也返回 `PowerOk=false`，该原始位不单独用于作出供电结论；仍保留原始值用于诊断。模拟模式必须明确选择，界面持续标注，不会从连接失败自动切换。

固件版本按厂家 `major.interim.minor` 格式读取。此前文档中的“0.51”缺少原始读回依据，已撤回；历史保存的结构体为实际版本 1.1.0、SDK 要求最低版本 1.0.0。当前通信失效，尚不能重新读取当前版本，不能据此判断固件过旧，也不能以版本号替代具体功能的实机验证。

## 控制器工具

X、Y、Z 各自显示一张通道卡片，标明配置映射后的 CH 编号；每张卡片独立提供输出使能、Home / Zero 和 Optimize，显示本通道的命令计数、输出状态及优化进度。操作不依赖共享的轴选择器。确认弹窗绑定点击时的轴和通道，设备或映射变化后撤销确认；驱动参数的通道选择仅作用于参数读取、导入和应用。优化期间仍禁止所有新的硬件动作，顶部保留「全部停止」。

位移台顶部增加「手动点动」「Home / Optimize / 参数」「运动记录」直达入口。滚动定位按固定控制栏的实际高度留出间距，手机布局也不会遮挡工具标题；跳转离开键盘点动区域会撤销键盘授权。

- 每轴独立启用/禁用输出，不自动移动。点动沿用原有自动使能行为，但只有单步模式和步数读回正确后才使能。
- **Home / Zero**：只在开环模式下清零控制器命令计数，不寻找机械原点，不测量位置；执行前明确确认含义。
- **Optimize**：调用官方 `TLMC_PZIM_PulseParaAcquire`，会由控制器自动驱动此轴，通常 1–2 分钟，不受点动步数限制。必须先使能并独立确认；优化期间所有新动作和参数修改被拒绝，全部停止保留。不会在连接或页面进入时自动优化，也不在部署验收时自动执行实机优化。
  后续采样须先观察到此轴优化/运动，再确认空闲，才能解除等待；旧的空闲样本不能解释为优化完成。未观察到进度或运动持续超过预期时，请求停止并锁存异常。
- 驱动参数：正/反向幅值、开环步频和加速度。先读取当前轴值及厂家范围，再独立应用并读回；切换轴/重连丢弃旧草稿。采用命名标量 `TLMC_SetSetting`，避免 PDXC2AD 缺少单位换算产品档案时批量 JSON 设置失败。应用失败不重试，须显式重新读取再允许运动；不会写入现场 `stage.json`，不额外调用设备持久化命令。

驱动参数支持导出最近读回值与导入 JSON 预览。导入前须先读取目标轴参数；校验格式版本、型号、完整字段、整数范围与目标控制器范围，导入不会发送任何硬件命令，核对后仍须独立点击应用。导出不包含未应用草稿。不额外调用设备持久化命令；参数断电后是否保持取决于固件。

Home / Zero 与输出使能操作增加状态读回校验，计数未归零或使能状态不一致会锁定为结果未确认。控制器工具独立显示最近 20 条 `stage_action` 记录，区分请求下发、读回确认、未下发、未确认、优化完成和停止。优化进度只显示控制器报告的阶段和等待秒数；失联时立即改为结果未确认。仅观察到优化/运动后再返回空闲，并且控制器报告优化成功标志，才记录“控制器报告优化完成”，不解释为机械到位。

**实机验收限制（2026-10-18）**：开环 Home / Zero 已通过真实控制器读回零的验证；一次已授权 Optimize 请求后，状态读取及停止确认超时，重新建立 SDK 会话和重置 USB 接口后仍不能取得设备应答，因此 Optimize 尚未通过实机验收。进一步绕过 XA，使用官方 FTDI 接口精确打开目标 USB 设备，硬件信息查询写入成功，但读取窗口内接收为零；这说明当前问题不只发生在网页或 XA 解析层，仍不能确定最初失效原因。网口亦仍存在 TCP 建立成功而硬件信息查询不应答的问题，已排除 USB 自动替代连接，并未宣称网口修复。Windows 识别到 USB 设备与 TCP 端口可连接均不能证明控制器命令处理正常。当前设备需现场确认停止与设备侧恢复，再继续硬件验收。

## 连接稳定性与恢复

XA GUI 与控制台轮流连接。XA 窗口关闭后可能仍残留进程；连接前检测该进程并给出退出提示。控制台使用按序列号的 Windows 全局互斥量，避免多个控制台实例抢同一设备。

原生 SDK 在独立进程中运行，所有 SDK 调用有进程外截止时间。卡死时释放本机会话并报告结果未确认，不会拖住真空采集，也不会重发任何控制命令。握手失败最多以新进程再尝试一次；不在同一进程反复 Startup/Shutdown，以免 XA 的 message-only window 残留。空闲时前两次读取失败暂停操作，只重试读取；第三次或运动中失败进入恢复流程。诊断显示采样耗时、有效采样数及连续失败次数。

“恢复失效连接”要求现场确认静止，必要时先断电重启控制器；释放失效句柄后只重新连接并检查空闲，不启用输出、不重发之前的运动。重新连接失败仍保持结果未确认。普通断开不能悄悄绕过未确认的停止。

移动或优化下发前，在运行数据目录原子保存 `stage-recovery.json`；保存失败时拒绝下发。后续采样确认空闲、停止确认或现场确认后恢复成功，才清除此记录。程序重启读到记录后继续锁住移动，禁止通过普通连接、断开或修改配置解除锁定；未确认错误会更新记录。该文件属于现场运行状态，不入库，不随部署覆盖。

## 安装与验证

Python 3.10+；依赖已固定为 `thorlabs-xa==1.8.0.28770`，Windows 打包脚本同时收集其本机库和许可证。普通开发安装：`pip install -r backend/requirements-dev.txt`。不需要安装完整 XA GUI 才能运行本控制台。

后端 API 包括 `GET /api/stage`、`PUT /api/stage/config`、`POST /api/stage/{connect,disconnect,move,stop,recover,action}` 和 `GET/PUT /api/stage/parameters/{axis}`。控制和参数接口受操作员权限保护，写操作校验 Origin。移动体保持 `{"axis":"x","direction":1,"steps":10}`；工具操作体为 `{"axis":"x","operation":"zero","confirmed":true}`。模拟测试与通信测试不代表机械运动已验证。

协议依据：Thorlabs XA Native API SDK 的 `TLMC_Startup`、`deviceDiscovery.interval`、`TLMC_DiscoverEthernetDeviceInfo`、`TLMC_Open`、`TLMC_Move`、`TLMC_Stop`；PDXC3 的三个子通道参照[官方 Python 示例](https://github.com/Thorlabs/Motion_Control_Examples/blob/main/Python/XA/PDXC3Subchannel/pdxc3_subchannel_test_script.py)。SDK 来源：[Thorlabs XA Python SDK](https://pypi.org/project/thorlabs-xa/1.8.0.28770/)。
